# Source Acquisition and Reference Hierarchy

## Purpose
Handle existing web and uploaded imagery without confusing source assets with reference intelligence.

## Source classes
### Primary source
Client-owned, client-authorized, or explicitly supplied production source. May be eligible for treatment/editing.

### Secondary reference
Used to learn direction, benchmark quality, composition, lighting, styling, or category behavior. Not automatically eligible to be copied, edited, or republished.

### Internal approved asset
Previously approved workspace asset with known lineage.

### Unknown/uncleared source
May be analyzed for research where lawful, but must not be treated as production-owned content.

## Website workflow
1. Receive primary website and optional secondary websites.
2. Discover candidate assets.
3. Record source URL and retrieval metadata.
4. Deduplicate.
5. Classify source role.
6. Assess usability: resolution, crop, corruption, watermark, duplication.
7. Preserve source lineage.
8. Select treatment or research path.
9. Never silently convert a reference-only asset into a production asset.

## Treatment path
Primary asset -> task classification -> locks -> treatment plan -> execution -> QC -> approved derivative.

## Reference path
Secondary reference -> deconstruction -> reusable observations -> comparison with existing brain -> candidate learning only.

## Rights discipline
The system must preserve the difference between technically accessible and authorized for production use.

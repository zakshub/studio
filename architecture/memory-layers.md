# Memory Layers

## Purpose
Prevent universal intelligence, client context, task state, and execution evidence from contaminating one another.

## Layer 1 — Canonical universal intelligence
Durable, reusable production knowledge that is brand-neutral and provider-neutral.

Examples:
- photographic reality
- source preservation
- material behavior
- camera/light logic
- anti-AI realism
- validated learned rules
- QC policies

## Layer 2 — Workspace context
Optional client/workspace-specific information supplied at runtime.

Examples:
- identity and positioning
- approved archive
- product catalog
- collection direction
- client-specific constraints

Workspace context is isolated from universal intelligence.

## Layer 3 — Task memory
Short-lived context for one job:
- objective
- sources
- references
- locks
- allowed changes
- target output
- approval state

## Layer 4 — Execution evidence
Internal record of what actually happened:
- executor/provider
- routing path
- QC
- failures/retries
- output IDs
- human approval/rejection

## Layer 5 — Research candidates
Unpromoted observations and hypotheses.

Research candidates are not canonical memory until promoted through the governed learning loop.

## Contamination barriers
- Workspace context cannot silently write to Layer 1.
- Task preferences cannot silently write to Layer 1.
- Provider quirks cannot become universal rules without scope.
- Research candidates cannot be treated as production truth.
- Execution records do not become rules by frequency alone; they require evaluation and promotion.

# Studio Brain Repository QA Checklist

## Brand neutrality
- No hard-coded client or brand identity in canonical operating rules.
- No client-specific preference promoted as universal truth.
- Runtime client context is explicitly isolated.

## Architecture
- Brain, workspace context, orchestrator, executor, QC, provenance, and learning are separated.
- Model/provider routing is task-specific and evidence-driven.
- Deterministic processing is allowed where AI is unnecessary.

## Privacy
- Front-end boundary hides repository topology, prompts, routing formulas, proprietary rules, hidden reasoning, and provider internals.
- Customer-facing outputs remain informative without exposing methodology.

## Source integrity
- Primary and secondary sources are distinguished.
- Rights/authorization status is represented.
- Strict preservation defaults to source truth.

## Learning integrity
- Research produces candidates, not automatic canonical rules.
- Duplicate/contradiction detection exists.
- Promotion and deprecation are traceable.

## QC
- Preservation, causality, anatomy, garment/material, camera/lens, lighting, color/post, and provenance are covered.
- Critical failures trigger rework.
- No aesthetic override of failed preservation.

## Anti-hallucination
- Never invent source provenance.
- Never claim a rule was read if it was not retrieved.
- Never claim a model/provider was evaluated without logged evidence.
- Never infer missing production-critical facts as confirmed facts.
- Unknown stays unknown until verified.

## Repository hygiene
- README points to current canonical architecture.
- SKILL reflects current operating contract.
- No orphaned conflicting rules.
- Changelog records promoted intelligence.
- QA is rerun after structural changes.
